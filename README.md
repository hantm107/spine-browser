# Spine Browser

A local Electron browser for Spine editor projects and exported animations.

## Append list

Use **Append +** on a library item to save it as an import source. **Append list** is a built-in global collection beside Favorites, independent of the active folder and custom categories. It keeps absolute file paths across restarts. **In Append** removes the bookmark while preserving the source files.

In the import workspace, choose a saved project under **From Append list** and click **Use as Import**. Main stays open and no folder picker is needed. You can also click **Import animation** on an entry in the library's Append list to open it directly as Import. **Add current source to list** saves a project already open in the Import pane, including a working project reconstructed from exports.

The library and import workspace share updates immediately. Missing files stay listed as unavailable; sources missing the required `images/` folder cannot be used until that folder is present. **Refresh list** rechecks availability. Saving an export still follows the existing working-project reconstruction flow when its folder has no `.spine` project.

## Import animations into another project

Open **Import → Import animation…** from the app menu, or select **Import animation** in the library. The separate workspace shows Main and Import side by side, with skeleton, animation, and skin selectors and independent playback timelines.

The workspace guides you through five steps: **Open projects → Choose animations → Names & images → Preview → Save project**. Later steps stay greyed out and unavailable until their prerequisite is complete. Open both projects, check your animations and select **Continue to names & images**, then configure and **Review import**. A successful **Preview merge** unlocks the final save step. The progress bar and Continue buttons take you between available steps. Changing the animation selection requires confirming it again; editing reviewed settings locks Preview and Save until you review and preview again. Large blue, purple, and green buttons highlight the main actions.

Each input must have a `.spine` file and an `images/` folder beside it, in separate project folders. Choose the intended `.spine` file if a folder contains several. When only a skeleton JSON or binary export is available, **Create working .spine copy** reconstructs a project and copies its images into the app's import workspace. Original files stay unchanged. An installed, activated Spine editor is required for this feature; configure its command-line executable under **Spine installation**. Ordinary library previews still work without the editor.

Legacy 2.x exports are reconstructed through Spine 3.8, which supports command-line import, then upgraded by Main when needed. Standard legacy binaries use the same decoder as library previews. Custom binary headers use a matching JSON export when present; unknown headers are never interpreted as editor version numbers. Source version metadata is retained, and attachment hide keys remain hidden. Spine 3.8.99 is requested when no 3.8 patch is installed.

Main and Import have blue and purple outlines and equal-width responsive previews. **Auto fit** follows the current visible pose during playback and scrubbing, excluding transparent effect attachments. It expands immediately for newly visible effects and eases into smaller poses. **Fit animation** switches to a fixed view of the full selected animation; turn **Auto fit** back on to follow the current pose. Click a preview to pause or resume; drag left or right to scrub and remain paused. The timeline slider is also available.

The importer reads fresh JSON from the saved projects, with nonessential data enabled. Main must use the same Spine version or a later version than Import. Earlier projects are converted by the Main editor in a working copy; version strings are never changed to bypass format compatibility. The matching editor versions must be available through the Spine launcher.

Under **Animations to import**, select one or more animations from the Import skeleton, or choose **Select all**, then **Review import**. **Clear selection** clears the checklist and disables review until you choose an animation. A batch creates one output project, one imported parent group, and one set of shared dependencies. Each selected animation keeps its own keys and timing. The dependency pass retains setup-visible attachments, ancestor and weighted-mesh bones, linked meshes, clipping and path dependencies, constraints, events, and referenced images needed by the selected animations. Unselected animations and their unused assets are excluded. With new skins enabled, imported artwork belongs to the new prefixed skins, including a skin for source-default artwork. The combined preview selects the matching imported skin automatically.

The Import pane's **Preview animation** selector follows the choice for a single-animation import. With multiple animations checked, changing the preview leaves the batch selection intact. A single animation supports **New animation name**. For a batch, the reviewed mapping table includes an editable animation row for each clip; names must be nonempty and unique. Editing a name requires another review. Use **Preview imported animation** in the combined preview to inspect any reviewed clip, then save them together. The saved project is re-exported and every imported animation's attachment selections are verified before publishing the result. The import report lists all source/output animation names and per-animation verification results.

Set **Import prefix** to name the imported parent group and new assets; it defaults to `ImportedMain`. The parent is created directly under Main's root at X = 1000, and later imports add a number (`ImportedMain2`, `ImportedMain3`, and so on). Bones, slots, attachments, skins, constraints, and events receive consistent names. Use **Find / Replace** or edit individual bone and attachment results; review again after each change.

After the first **Review import**, **Image sequences** lists numbered image groups used by the selected animation, separated by source folder and skin. Detected, unambiguous groups start with short replacement names such as `Sequence1_001.png`. Set **New name (before number)**, an optional suffix, starting number, and zero padding, then review again. This replaces the original naming completely: `Lightning_` produces `Lightning_001.png`, without adding source folders, skin names, or import prefixes. Turn off **Replace the original names** for a group to keep the standard generated names. The filename preview sorts frame numbers numerically and closes gaps: `2, 4, 8, 10` can become `001, 002, 003, 004`. Attachment names, image paths, deformation/linked-mesh references, and attachment keys update together; source images and keyframe times stay unchanged. The same source image reused across several slots is counted once, renamed once, and copied once. Each slot keeps its own attachment, transforms, and animation keys; the sequence UI shows how many slots share the images. Genuinely different images with the same frame number, or distinct attachments sharing an image inside one slot, remain flagged to prevent merging unrelated data. Output name collisions also block saving.

For native Spine sequence attachments, the number must remain last, so suffix text is placed before the number. The preview shows this layout; sequence start/padding changes while frame indices, setup frame, count, and timing remain intact. Sequence-managed mapping rows are read-only until that group is disabled and reviewed again. **Reset to short new names** reviews the import again with fresh replacement names. Automatic names skip names already used in Main.

**Images subfolder** is required. Enter a name such as `Effects/Impact` to store the new images under Main's `images/Effects/Impact/`. Every import uses a fresh subfolder: an existing name becomes `Effects/Impact-2`, then `Effects/Impact-3`, and the review shows the exact destination. The initial folder name follows the import prefix until you edit it. Attachment display names match the copied image filenames without the extension, and their image paths include the selected subfolder. Image sequences retain their numbered-frame naming. Existing Main images keep their paths. Blank or invalid folder names and missing required files stop the import.

**Create new skins for imported attachments** is enabled by default and appends the prefixed source skins. Select the indicated imported skin in Spine to display its artwork; the combined preview does this automatically. Turn this option off to use the **Import preview skin** selection, including its default-skin fallbacks, and add its required attachments to Main's default attachments without creating named skins. Linked meshes, deformation keys, skin-required bones, and constraints are retained for the selected variant. Review again after changing these options or the selected Import skin.

**Preview merge** plays a selected imported animation alongside Main's setup pose. **Save into Main folder** is the default: it creates a new `.spine` file beside Main and puts the new images in the reviewed subfolder. No output-folder picker is needed. Main's existing animations and other skeletons are retained; the new animations contain only remapped Import timelines. Use **Use result as Main** to perform another import.

**Save the new project beside Main** starts enabled. The app creates a file such as `Main-ImportedMain.spine` and an accompanying import report. Existing project files and assets are preserved, and an existing output project name receives a numeric suffix. The project is first saved and re-exported in a working folder to verify every attachment selection key and imported setup attachment. A changed or nullified selection stops the save before Main is updated. If the reviewed image subfolder is created by another process before saving, review again to choose a fresh name.

Uncheck **Save the new project beside Main** to create a separate output folder instead. That mode asks for a location outside the source folders and includes `Merged.spine`, the original Main images, the new image subfolder, and the import data and report. The mandatory image subfolder rule also applies to this mode.

The new `.spine` project is rebuilt through Spine's official export/import workflow. Editor-only state that is absent from exports cannot be preserved. Existing missing images in unselected Main skeletons are reported in the review and import report; missing images needed by the selected skeleton or animation block saving. Audio referenced by events is copied from each project's `audio/` folder when used. Ambiguous or unsupported data fails with an explanation instead of dropping keys.

## Browse and preview

Preview discovery accepts both `.atlas` and Unity `.atlas.txt` files, including uppercase extensions and multiple texture pages. When both atlas forms have the same name, `.atlas` takes priority. Source exports do not need to be renamed. When a binary has an unsupported or custom version header, project and binary previews use a supported JSON export with the same filename stem when available. The preview status identifies this fallback; source files remain unchanged.

Use Left/Right to browse adjacent files and Up/Down to move between visual rows in the library. Highlighting updates immediately; the preview loads after 200 ms without another arrow press, so holding a key skips intermediate loads. Navigation follows the current search/category filters and scrolls the highlighted card into view. Arrow keys retain their usual behavior in text fields and controls. Click the animation canvas to pause/resume, or drag left/right to scrub the animation while paused. The selected asset has a bright green outline.

Preview blending supports Normal, Additive, Multiply, and Screen with straight-alpha and premultiplied atlas textures. Textures are normalized to premultiplied alpha in GPU memory per atlas page (`pma: true` pages are not multiplied twice). Older Screen blending uses the corrected destination-color factor. The source atlas, textures, and skeleton blend settings are never rewritten.

Legacy **Spine 2.0 and 2.1** JSON and binary skeleton exports are supported alongside the existing 3.x and 4.x runtimes. Native 2.x animation behavior includes bone flips, IK, weighted meshes, and FFD. Related `.spine` projects can preview their accompanying exports as usual. Unversioned legacy JSON uses a clearly labeled 2.1 compatibility fallback; unversioned/`Dev` binary exports cannot be safely identified and remain unsupported. Reference coverage and archive-specific limitations are documented in [vendor/README.md](vendor/README.md) and [tests/fixtures/README.md](tests/fixtures/README.md). Original assets are never rewritten.

The library uses the left half of the window, with a dedicated category column and a full-height file browser beside it. List and grid views automatically add columns as space permits. The smaller animation preview and playback controls occupy the right half.

The original app code is covered by the repository's [MIT license](LICENSE). Bundled and derived Spine runtime code, compatibility readers, and upstream sample assets retain their upstream license terms; see [vendor/README.md](vendor/README.md) and [tests/fixtures/README.md](tests/fixtures/README.md). The MIT license does not replace those third-party terms.

```sh
npm install
npm start
```

To build a portable Windows x64 executable, run `npm ci` followed by `npm run build:win`. The result is `dist/Spine-Browser-1.6.0-portable.exe`; users can run that single file without installing Node.js. Browsing exports works without Spine; native project importing requires an installed, activated Spine editor. The app is unsigned, so Windows may display an unknown-publisher warning. Build output excludes test fixtures, snapshots, temporary files, and local settings. Upload the executable as a GitHub Release asset; keep generated builds out of the source repository.

`node tests/packaged-smoke.cjs` launches the generated executable with a temporary user profile and checks JSON and binary playback using the checked-in fixtures. It saves results and a screenshot under `.temp/`.

Choose an asset folder, then select a file to preview it. Search matches file names and folders. The animation controls let you pause playback or choose another animation; the buttons below the preview open the selected file in Explorer or Spine.

Version 1.1 groups related `.spine`, `.json`, and `.skel` siblings into one asset. Expand **Related files** to preview a specific member. Ambiguous skeletons stay separate. Search includes the names of all group members.

Each animation has its own wrapping button. The shared toolbar provides pause/play, restart, loop/play-once, speed, timeline scrubbing and forward/backward frame stepping. Frame stepping uses the export's FPS when available, otherwise 30 FPS. Skin selection remains available for exports with multiple skins.

The app restores the last folder, selected asset, search, library scroll, list/grid view, favorites filter, playback speed, loop mode, and animation choice. **Recent folders** remembers the last ten folders; **Rescan folder** refreshes the current library. A missing folder produces an error and leaves Choose folder available.

Each collection remembers its own selected asset, search, and scroll position. Visit **Favorites**, **Append list**, or a custom category, then return to **All assets** to resume browsing where you left off. This position is retained when the app restarts while another collection is open.

Use the star on an entry to bookmark it and **Favorites** in the Categories section to open your global bookmarks across all folders. Favorites store absolute file paths and can be previewed regardless of the active folder. Existing bookmarks migrate automatically. Missing or moved files stay bookmarked with an unavailable status, and their full paths remain visible. **Grid** shows larger thumbnail cards. Thumbnails are captured as you preview visible assets, rather than rendering the entire collection in the background. Pause at a useful frame and press **Update thumbnail** to replace a thumbnail. Thumbnail PNGs are cached in Electron's user data directory; original assets are never modified.

A source snapshot of version 1.0.0, before the UX changes, is saved locally under `snapshots/spine-browser-before-ux-20261023-112128.zip`. Extract it into a separate folder and run `npm ci` followed by `npm start` to restore it. Installed dependencies, personal editor state, and generated reports are excluded from that snapshot.

Tick **Hide .skel files** above the file list to hide standalone binary exports. The setting is remembered between sessions; `.spine` projects continue to use their associated exports for playback.

Supported playback versions: **Spine 3.0, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 4.0, 4.1, 4.2, and 4.3**, for binary `.skel` and JSON exports. The app detects the export version and loads its local runtime or compatibility adapter automatically. Switching folders or versions requires no setting changes or re-export. Previews work offline and do not launch the Spine editor. Unsupported or malformed files display an explanation instead of being sent to an incompatible parser.

Skeleton `.json` files appear in the file list and preview directly, just like `.skel` files. Ordinary application JSON is ignored. JSON files remain visible when **Hide .skel files** is checked. Uppercase `.JSON` extensions and UTF-8 files with a byte order mark are supported.

For playback, place a `.skel` or skeleton `.json` beside an atlas with the same base name and all the atlas page images. If the folder contains only one skeleton and one atlas, their names can differ. A `.spine` project can use a matching export in its folder. A numbered project such as `001.spine` can also use the folder's only skeleton, including when it is exported as both JSON and binary. Folders with ambiguous exports require matching names. Raw editor projects can be opened in Spine but cannot be rendered directly.

The original project and export files are never overwritten. The 3.0-3.5 binary formats are decoded in memory. Versions 3.0-3.4 use the shared 3.4 renderer; 3.5 uses the 3.6 renderer with its own binary layout. Earlier mesh and constraint names are normalized without changing source files. Version routing covers every released 3.x minor series; individual experimental beta layouts are not guaranteed. The 4.2 player is pinned to 4.2.120, the latest published 4.2 package verified during this update. The bundled legacy runtime's source and license are documented in [vendor/README.md](vendor/README.md).

Run `npm test` for asset-resolution/version/scanning regression tests and actual Electron playback/UI checks. The Electron tests briefly show a test window to verify animation advances, then close it. Verification results and a sample screenshot are saved in `.temp/`.

Native-editor attachment regression checks are available with `npm run test:import-native`. Set `SPINE_NATIVE_IMPORT_CLI` to the installed Spine command-line executable and `SPINE_NATIVE_IMPORT_VERSION` to an installed editor version (defaults to 4.2.43). These checks require activation and exercise real save/reopen behavior; ordinary tests do not launch Spine.

Spine 3.8.75 JSON and binary exports receive best-effort preview support. The upstream runtime rejects this editor version because of known export bugs (https://github.com/EsotericSoftware/spine-runtimes/issues/2428). The version guards are relaxed while the standard data readers remain unchanged. Original version metadata is preserved and source files are never rewritten. Verified locally with lrsc502/lrsc532 JSON and the 233/228 binary exports; damaged files may still require re-exporting. Default playback skips zero-duration placeholders when animated clips are available.

Version 1.2 adds a **Categories** sidebar section with **All assets**, **Favorites**, and **custom categories without an app-imposed count limit**. Create a category with the name field and + button. Each category automatically receives a unique RGB color. The original eight colors are preserved; additional colors are generated as needed, with collision checks. Click **Tags** on an asset and use the large category toggle buttons to add or remove memberships; selected buttons show a checkmark. The red **Close** button is at the bottom of the popup. its colored name tags appear directly on the asset card in both list and grid views. Click a tag or category name to browse that global collection. Use the category menu to rename or delete it. Names must be unique (case insensitive) and at most 40 characters. Deleting a category requires a second confirmation click and preserves original files, Favorites, and other memberships. Category colors, membership, and selected collection are remembered across restarts using absolute paths.
